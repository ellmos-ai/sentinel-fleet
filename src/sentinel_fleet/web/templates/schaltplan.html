Interaktiver Architektur-Schaltplan (Google Cloud Hackathon Blueprint)

End-to-End Datenfluss: Event Ingestion → Model Armor → Multi-Agent Conductor → Gemini 3.5 Flash → Memory Bank → Firestore → Cloud Trace

1. Event Ingestion & Input Channels (Pillar UAS & Google Cloud Pub/Sub)
Eingehende Dokumente (PDF-Rechnungen, E-Mail-Anhänge, Scans, API-Payloads) triggern asynchrone Jobs via Google Cloud Pub/Sub oder REST-Endpunkte.

2. Zero-Trust Gateway & Model Armor (Pillar Control)
Jeder Request durchläuft die Model Armor: Prompt Injection Defense, PII-Maskierung (IBAN, API-Keys) und Zero-Trust Permission Check (LOCK.permissions.json).
lock-master anonymizer Model Armor Guard Principle of Least Privilege (PoLP)
3. Multi-Agent Conductor & Gemini 3.5 Flash Vision (Pillar Control & Conductor)
Der Roshambo Swarm Conductor und Clutch Router delegieren Subtasks an isolierte Agenten (Extractor, Auditor, Reconciler, Dispute Communicator).

4. Memory Bank & Context Injection (Pillar Memory)
MemoryHooker injiziert relevante Firmenrichtlinien (USMC Fakten & GARDENER RAG Chunks) dynamisch in die Prompts der Sub-Agenten.
USMC Memory Bank GARDENER FTS5 / Vector RAG memory-hooker
5. § 14 UStG Compliance Audit & Self-Healing Loop (Pillar Domain: OmniLedger)
Gültige Belege werden direkt im Firestore Ledger verbucht. Bei Mängeln (fehlende USt-IdNr, Rechenfehler) generiert der Agent autonom ein Korrekturschreiben und übergibt es an das Human-in-the-Loop Ticket-Gate.
